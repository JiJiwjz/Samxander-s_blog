# 前言

我们有一台 7 自由度机器人机械臂，挂载在我们的关节式履带机器人上。我的目标是实现机械臂能够实现瓶盖的**抓取、旋拧**等操作。

我们最初通过手柄遥操作机械臂完成瓶盖抓取与旋拧任务，但实际上，这强依赖于人工操作，不仅在比赛里拿不到高分，在当今也显得有些落后，缺乏智能性。

为此，我设计并实现了一套基于**视觉伺服**的闭环系统，实现从目标感知、位姿估计到控制执行的自动化操作。

# 属于机械臂岗维护的设备

- 7-DOF 机械臂；机械臂上的**深度摄像头**，型号为 **OAK-D-SR**；夹爪中间的摄像头；
- **ChArUco 航空铝基板 标定板 * 1**，尺寸为 300 * 200mm，方格边长 20mm，二维码尺寸 15mm，图案阵列 149；
- USB 3.0 1m / 2m 数据线若干。

# 感知模块

首先我们的机械臂，肯定需要知道瓶盖相对于摄像头的相对位置，才能完成夹取任务（为什么是相对于摄像头而不是夹爪？请往下看）。那要怎么获取位置信息呢？这并不是一简单的问题，我拆解为了下面几个模块：

## 基于 YOLO 的实例分割模型

我设计了一个轻量级视觉感知模块，使用了**实例分割**模型 YOLO11n-seg。至于为什么选用 nano 型号，是我对模型性能和实时性要求的一个平衡；模型太重会影响实时性。

首先，我们要获取瓶盖的数据集。在做数据集的过程中，我只拍摄了大约 100 张照片，数据量较小。因此我对数据做了数据增强，增强后差不多能等效为上千张照片的效果。

随后用我的电脑进行了**模型训练**，并进行基于图片/视频的推理测试。由于这个实例分割模型更倾向于工程化的使用，因此不太需要观察性能上的指标，比如 mAP，IoU 等，而是人为观察其基于图片、视频进行推理的效果是否不错，是否有标记错误，置信度过低的情况，结果发现在光照条件一般的情况下，也能出现精准的分割。

但是感觉数据仍然不够，因此后面可能会考虑补充数据集，比如在不同角度、不同光照、不同背景等情况下拍摄。

>待做 1：补充数据集。

## 模型框架的转换

我们项目的代码实际上都是基于 C++ 构建的。然而我们直接训练出来的模型基于 PyTorch 框架，只能在 Python 下进行推理。

此外，在 PyTorch 框架下进行推理，处理速度较慢，对单张图片进行推理的时长超过了 50ms。

综合以上两个原因，我们急需一种新的方案在既能保持性能的同时，还要能够在 C++ 下进行推理。

因此，我们最终选择了 **TensorRT**。在这个框架下，单张照片的分割速度到达了 20ms 上下，并且依赖 C++，这符合我们的要求。

我们采用了由 PyTorch 到 ONNX 再到 TensorRT 的转换链路。基于下面的开源项目实现：

[https://github.com/emptysoal/TensorRT-YOLO11](https://github.com/emptysoal/TensorRT-YOLO11)

这个项目支持 YOLOv11 的转换，后面我们要换成 YOLO26，所以后面还需要重新进行转换。

>待做 2：更换为最新的 YOLO26 模型。

最终得到的权重文件为 .plan 文件。我们编写 C++ 代码，就可以进行瓶盖的视频推理。

## 从掩码到瓶盖对准

实例分割得到的结果只是 mask，即掩码，它是**缺乏几何信息**的，因此无法直接用于控制。又由于实际情况下环境/背景的复杂性，跳过深度学习直接使用霍夫圆检测是不可行的。

我想到了一个“深度学习 + 几何拟合”的融合方法。我对分割区域进行了（椭）圆形的拟合。这实际上是利用了瓶盖是圆形的**先验**。

首先对获得的（椭）圆，我们等距提取 8 个边缘点，每一个边缘点到摄像头的距离记作 $d_i$。

>疑点 2：8 个边缘点够吗？可能要根据实际情况增加。

如何判断摄像头对准了夹爪呢？我们结合了深度信息 

$$
\{d_{i}\}_{i=1}^8
$$

和圆形的离心率等信息作为判据：

- 当 8 个边缘点到深度摄像头的距离彼此接近相等（待做 3：彼此接近相等的判据）；
- 当椭圆的离心率接近于 0（即接近一个圆形）；
- 当瓶盖圆心位置几乎与图像的中心点重合。

当以上三个条件均满足时，可以确定摄像头此时对准了瓶盖。**那如何驱动机械臂移动，以达到“对准”的目的？这部分就放在在后面 PID 部分进行介绍了。**

>疑点 3：这三个判据可能仍不鲁棒。可以考虑相机平面的法向量，需要和瓶盖盖面所在平面的法向量平行。网上有人建议 PnP，可以研究一下。

# 真的对准了吗？

实际上，摄像头与夹爪位置之间有明显差异，即使视觉对准了，夹爪仍然是抓不准。

因此，我引入了手眼标定，通过标定板求解 **摄像头坐标系** 到 **机械臂（夹爪）坐标系** 的变换矩阵。接下来，就能通过机械臂的运动，实现让夹爪夹准瓶盖；

怎么求解这个变换矩阵呢？我们基于 ChArUco 航空铝基板进行手眼标定。具体细节后面再补充。

# MoveIt!：运动规划与安全执行

前面的感知模块解决了“瓶盖在哪”的问题，但是怎么安全的把机械臂移过去，也是一个很重要的问题。纯依靠 PID 做大范围运动是危险的，因为它不知道关节限位情况，以及是否会碰撞。

因此需要引入 MoveIt! 作为运动执行层。整体采用了著名的“Move-then-Servo”的策略。MoveIt! 负责大范围的无碰撞路径规划，将机械臂从待机姿态移动到瓶盖上方的预备位置（**考虑在 Rviz 里进行拖拽**，把末端执行器拖动到能使摄像头看到瓶盖的距离，但注意要让摄像头**保持在深度相机工作距离范围内**）。

此外，MoveIt 还承担以下职责：

- **逆运动学求解。**PID 输出的笛卡尔空间增量，通过 MoveIt 内置的求解器转换为关节角指令，省去手写雅可比逆的麻烦；
- **抓取与旋拧的轨迹规划**；
- **碰撞检测**。

# PID：用摄像头“调教”机械臂

如何让机械臂夹爪能够“**自动对准**”目标？解决方案就是视觉伺服。我设计了一个闭环控制系统，输入是图像中的偏移量，随后基于 PID 算法进行底层控制，最终输出机械臂的运动指令（这实际上实现了一个闭环反馈系统）。在上位机中进行视觉处理和偏移计算，下位机进行电机控制和状态反馈。最终实现了机械臂能够自动调整姿态，使瓶盖逐步对准摄像头。
